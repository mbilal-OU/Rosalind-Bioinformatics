# Verification and publication standards

## Responsible public scope

Rosalind explicitly requests that users do not publish solutions outside the platform. This repository therefore contains **original learning notes and applied demonstrations**, not direct Rosalind solution files, answer datasets, or challenge-by-challenge output.

Official sources remain the authority for challenge wording, datasets, grading, and current track counts:

- [Rosalind problem locations](https://rosalind.info/problems/locations/)
- [Rosalind FAQ](https://rosalind.info/faq/)

## Private verification standard

A private exercise implementation may be marked verified only when all conditions are met:

1. The approach is written in the author’s own words.
2. Unit tests cover the supplied-style case plus independently constructed edge cases.
3. Output formatting and numerical tolerance are checked.
4. Runtime is appropriate for the task’s stated constraints.
5. The author receives an accepted result from Rosalind.

## Public quality standard

A public method or capstone must include:

- a clear biological motivation
- original, openly usable data or simulated inputs
- documented assumptions and limitations
- reproducible commands or notebooks
- tests where behaviour is deterministic
- citations for external methods, software, and datasets
- no unsupported performance or completeness claims

## What “complete” will mean

The phrase **Rosalind-complete** will be used privately only after every exercise in the live official catalogue has reached Verified status. The public repository will describe its own public content precisely and will not imply that code or answers are available here.
